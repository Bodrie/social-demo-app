# The Mesh – notes for AI-assisted development

## State of the repo

- v2 is the whole repository: the 2026 rebuild replaced the original Express/CRA app (phases 0–7 in `docs/REBUILD_PLAN.md`, decisions D1–D23 as ADRs in `docs/adr/`). Add a new ADR instead of silently changing a decision; park deferrals in `docs/BACKLOG.md`.
- Code lives in `apps/api` (NestJS 12, ESM), `apps/web` (Vite 8 + React 19), `packages/shared` (zod schemas, constants; built with tsdown) and `packages/config` (tsconfig + oxlint presets); `deploy/` holds the production stack (see `docs/RUNBOOK.md`).

## Commands (run from the repo root)

| Command | What it does |
|---|---|
| `pnpm install` | install every workspace (pnpm 11, Node 24, see `.nvmrc`) |
| `pnpm dev` | turbo: build `shared` once, then watch `shared`, `api` (`nest start --watch`) and `web` (`vite`) |
| `pnpm check` | `turbo run lint typecheck test build` – identical to CI |
| `pnpm test:int` | API integration tests (`apps/api/test/*.int-spec.ts`, supertest over HTTP) |
| `pnpm --filter @the-mesh/web e2e` | Playwright against the built API (`apps/api/dist`) + `vite preview`, seeded DB; `pnpm build` first, `… exec playwright install chromium` once; `e2e:ui` for the inspector |
| `pnpm format` / `pnpm format:check` | Prettier, root `.prettierrc`; CI fails on drift |
| `pnpm db:up` / `pnpm db:down` | PostgreSQL 17 via docker compose on `localhost:5433` |
| `pnpm db:generate` | regenerate the Prisma client into `apps/api/src/generated` (turbo runs it before api tasks) |
| `pnpm db:migrate -- --name <change>` | create + apply a migration from schema changes (dev DB) |
| `pnpm db:deploy` / `pnpm db:check` | apply committed migrations / fail if DB and schema differ |
| `pnpm db:seed` | **truncates everything**, then loads deterministic demo data (alice/bob/carol, password `Password123!`) |
| `pnpm db:studio` | Prisma Studio |
| `pnpm --filter @the-mesh/api <script>` | run one workspace's script |
| `docker build -f apps/api/Dockerfile .` / `-f apps/web/Dockerfile .` | production images (context = repo root; on this WSL box prefix with `DOCKER_CONFIG=<dir with {"auths":{}}>`) |
| `cd deploy && docker compose up -d` | the production stack (see `docs/RUNBOOK.md`; `--profile tunnel` adds cloudflared) |

## Conventions

- TypeScript 6.0, `strict` + `noUncheckedIndexedAccess` (from `packages/config/tsconfig/base.json`). Configuration is kept TypeScript-7-clean (no `baseUrl`, no `node10` resolution); see ADR 0007.
- Versions are pinned exactly in the `catalog:` of `pnpm-workspace.yaml`; workspaces reference them as `"catalog:"`. When adding a dependency, put its version in the catalog.
- ESM everywhere. In `apps/api` and `packages/shared` (`module: nodenext`) relative imports carry the `.js` extension: `import { x } from './x.js'`.
- `packages/shared` is consumed from its `dist/`; turbo builds it before dependants (`dependsOn: ["^build"]`). Run `pnpm --filter @the-mesh/shared build` after changing it if you are not using `pnpm dev`.
- Lint: oxlint with `--type-aware`, per-workspace `.oxlintrc.json` extending `packages/config/oxlint/base.json`. Format: Prettier only (no ESLint).
- Tests: Vitest in every workspace. Naming: `*.spec.ts` unit tests next to the source in `apps/api`; `*.test.ts(x)` in `apps/web` and `packages/shared`; `test/*.int-spec.ts` integration tests in `apps/api`.
- Validation schemas and DTO types that both the API and the web need go in `packages/shared` (zod 4), never duplicated. In the API a DTO is `class XDto extends createZodDto(xSchema) {}` (nestjs-zod); the global `ZodValidationPipe` validates bodies/queries/params typed with such DTOs.
- API conventions (`apps/api/src/app.setup.ts`, `common/filters/http-exception.filter.ts`): routes live under `/api/v1`; `GET /health` is outside the prefix; every error is the shared `ApiError` envelope `{ statusCode, code, message, fields?, requestId }` (throw Nest `HttpException`s, optionally with `{ code, message, fields }`; Prisma P2002/P2025 are mapped automatically; unexpected errors become a masked 500 and are logged); every response has `X-Request-Id`; Swagger UI at `/api/docs` and JSON at `/api/docs/openapi.json` outside production.
- Logging: inject `Logger` from `@nestjs/common` (backed by pino via nestjs-pino); pino-style calls `logger.log({ userId }, 'message')`. Never `console.log` in `src/`.
- Rate limiting: `ThrottlerGuard` is global (`THROTTLE_*` env); tighten per route with `@Throttle({ default: { limit, ttl } })`, opt out with `@SkipThrottle()`.
- Auth: the `AuthGuard` is global, so every route needs a session unless the handler or controller has `@Public()`. Read the caller with `@CurrentUser() user: AuthUser` (`{ id }`). Tokens live in httpOnly cookies (`access_token` 15 min JWT, `refresh_token` single-use, scoped to `/api/v1/auth`); a `Bearer` header works too. Never trust ids from the request body for authorisation.
- Errors: use the helpers in `common/errors.ts` (`notFound`, `badRequest(message, fields?)`, `conflict`, `forbidden`, `unauthorized`, `validationError(fields)`); the filter derives `code` from the status. `UsersService.assertAvailable` is the shared uniqueness check; `UsersService.assertExists` / `PostsService.assertExists` for 404s on referenced ids.
- Route params go through the zod DTOs in `common/params.dto.ts` (`@Param() params: IdParamDto`), never `ParseUUIDPipe`, so malformed ids are `VALIDATION_ERROR`s keyed by the parameter.
- Every "me" response is `{ user: UserPrivate }` (`meResponseSchema`); every list is `{ items, nextCursor }` even when it is not paginated yet.
- Credential routes (login/register) are marked `@CredentialRoute()`; that is what applies the per-account and per-address throttlers from `auth/credential-throttle.ts`.
- Realtime: `ChatGateway` (socket.io, same port) authenticates at handshake only; the global `AuthGuard`, `HttpThrottlerGuard` and `HttpExceptionFilter` skip non-HTTP contexts, so never rely on them inside `@SubscribeMessage` handlers: validate payloads with the shared zod schemas and answer with an ack `{ ok, message | error }`. Deliver server pushes from domain events (`@OnEvent` in the gateway, rooms `user:<id>`), so HTTP and socket paths behave the same. Presence is in-memory (single instance).
- Domain events: services `await this.events.emitAsync(Event.EVENT, new Event(...))` (classes in `src/events/`), so listeners finish before the response. Listeners (`@OnEvent`) must never throw; wrap their work in try/catch and log. `ActivitiesListener` is the model.
- Lists: keyset pagination everywhere (`cursorQuerySchema` in shared; `decodeCursor` → `{ createdAt, id }`, `keysetAfter(cursor, idWhere)` in the `where`, `paginate`/`paginateBy` in `common/pagination.ts`; order `createdAt desc, id desc`, fetch `limit + 1`). Never use Prisma's `cursor:` option: it breaks when the cursor row is deleted and drops the SQL `LIMIT` on composite keys. Feed-style items are shaped by a `select` function that takes the viewer id (e.g. `postSelect(viewerId)`) so counts and `likedByMe` come from the same query; map rows with the module's `to*` mapper.
- Uploads: files are written through the `StorageService` interface (`@Inject(STORAGE)`), never with `fs` directly, so object storage can replace the local disk later. Keys look like `avatar/<uuid>.webp`; records store keys, responses expose URLs via `assetUrl()`. Every upload has an owner row (`uploads` table). Validate a client-supplied key with `UploadsService.assertOwned(key, { ownerId, kind, field })`; `discard(key)` deletes the file only when no profile or post references it. Local files live in `UPLOADS_DIR` (`apps/api/uploads`, gitignored); integration tests get a temp dir.
- Integration tests: `createTestApp({ listen? })` (`test/setup/app.ts`) boots the real app on the test DB with empty tables (`listen: true` binds a port for socket.io clients); the developer `.env` is ignored under `NODE_ENV=test`; `createUser(prisma)` / `login(agent, email)` in `test/setup/factories.ts`; use `request.agent(server)` so cookies persist. The shared test password is `Password123!`.
- Web app (`apps/web`): `@/*` maps to `src/*` (`paths` in `tsconfig.app.json` **and** the root `tsconfig.json`, which is what the shadcn CLI reads; without it `shadcn add` writes into a literal `./@/` folder). Relative imports have no extension. Layout: `app/` (providers, query client, router, route guards), `features/<area>/` (pages, hooks, api helpers, tests), `components/` (shared pieces; `components/ui/` is generated by `pnpm dlx shadcn@latest add <name>` and exempt from the stricter lint rules via an override — edit sparingly, prefer wrapping), `lib/` (api client, env, query keys, small helpers), `test/` (Vitest setup, MSW handlers/server, render helpers, fixtures).
- Web data: all requests go through `lib/api/client.ts` (`api.get(path, schema)`, `api.post(path, body, { schema })` …): responses are parsed with the shared zod schemas, failures throw `ApiClientError` (`.status`, `.fields`, `.error`), a 401 triggers one silent refresh and retry (pass `retryOnUnauthorized: false` on the auth endpoints). TanStack Query keys come from `lib/query-keys.ts` (first segment = feature, so `endSession` can drop everything but `me`). Mutations map API `fields` onto react-hook-form with `applyApiErrors`; anything else is a toast (`sonner`).
- Web session: `useMe()` is the only reader of the `me` query for routing decisions; inside protected routes use `useCurrentUser()` (context provided by `RequireAuth`), never `useMe()`. After login/register call `startSession`, after logout `endSession`; the guard routes do the navigation, pages do not call `navigate()` for auth transitions.
- Web design: colours, radii and fonts come only from the tokens in `apps/web/src/index.css` (oklch, light + `.dark`), exposed as Tailwind utilities (`bg-card`, `text-muted-foreground`, `text-like`, `bg-online` …); never hard-code a colour in a component. Icons from `lucide-react`; primitives from `components/ui`; shared states in `components/empty-state.tsx` (`EmptyState`, `ErrorState`) and per-feature skeletons. Each page sets its title with `usePageTitle()`.
- Web lists: cursor lists are `infiniteQueryOptions` with `initialPageParam: NO_CURSOR` and `getNextPageParam: (p) => p.nextCursor ?? undefined`; the cache shape is `Pages<T>` from `lib/infinite.ts` (`flattenPages`, `mapItems`, `filterItems`, `prependItem`); load more with the `useInfiniteScroll` sentinel. Post lists share the `queryKeys.posts.lists` prefix and are changed only through `features/posts/post-cache.ts`; people (profiles + every user list) through `features/users/user-cache.ts` (`updateUserEverywhere`). Likes and follows are optimistic: snapshot with `snapshotQueries`, roll back in `onError`, never refetch what the optimistic update already made correct. Reuse `PostList` / `UserList` for any new list instead of building a loop.
- Web discovery: `UsersPage` (`/users`, search via `useDebouncedValue` + `?q=`), `SuggestionsCard` and `ActivitiesCard` in the right bar, `/activity` page; activity sentences live only in `features/activities/activity-text.tsx`. In jsdom the right bar renders on every page, so scope test queries (`within(...)`) when a page and the sidebar can both show Follow buttons or lists.
- Web chat: the socket is owned by `features/chat/chat-provider.tsx` (never call `io()` elsewhere; `useChat()` gives `sendMessage`, `markRead`, presence). Pushes are mirrored into the query cache through `features/chat/message-cache.ts`; threads are cached newest-first. In tests the socket is `fakeSocket` from `src/test/socket-mock.ts` (`serverEmit`, `serverDisconnect`, `emitted`); wait with `waitFor` after a push.
- Web routing/perf: new pages are `lazy` routes in `app/router.tsx`; a feature with several route components exports them from one `routes.tsx` so they share a chunk. Keep the first paint small: `pnpm build` fails when the initial JavaScript passes the budget in `scripts/bundle-budget.mjs` (raise it only with a reason in the PR). Heavy optional UI (emoji picker, socket client) is imported dynamically.
- Web accessibility: every page must pass `e2e/a11y.spec.ts` (axe, WCAG 2.1 A/AA, light and dark); add new pages to it. Icon-only controls need `aria-label`; controls with visible text must keep that text in their accessible name; scrollable regions get `tabIndex={0}`; colours stay within the tokens (contrast was checked for them). Focus moves to `<main>` after navigation from the shell, so pages should start with their heading.
- Web profile: `/u/:username` is a layout route; tab routes read the loaded user with `useProfileContext()`. Profile edits go through `buildProfilePatch` (diff only) and `useUpdateProfile`; pictures through `ImageField` + `useImageUpload(kind)`.
- Web dev/preview proxy `/api` and `/socket.io` to `VITE_DEV_API_URL` (default `http://localhost:3000`), so the app is same-origin with the API and cookies just work; leave `VITE_API_URL` empty unless the API really lives elsewhere.
- Web tests: Vitest + jsdom + Testing Library + MSW (`src/test/setup.ts` starts the server with `onUnhandledFrame: 'error'`, so every request a test triggers needs a handler in `src/test/msw/handlers.ts` or a `server.use(...)` in the test). `renderApp(route)` mounts the real router + providers; `renderWithProviders(ui)` for single components; `signedInAs()` / `mockSession` control the mocked session. Query by role/label, never by class. Mock data: `mockDb` (users alice/bob/carol, follows, posts, comments, uploads) + `seedPosts()` / `seedFollow()` + fixtures (`makePost`, `makeComment`, `alice`/`bob`/`carol`); `mockDb.user` is the signed-in user, `toPublic()` derives the public shape; the setup swaps `FormData`/`Blob`/`File` for Node's (MSW runs on Node's fetch), stubs `URL.createObjectURL` and installs a controllable `IntersectionObserver` (`intersectAll()` from `src/test/intersection-observer.ts`); pass `{ applyAccept: false }` to `user.upload` for files the input's `accept` would filter. Playwright specs live in `apps/web/e2e/`: the `seed` project reseeds the database, the `setup` project signs in alice, bob and carol once and stores cookies (`e2e/.auth/`, gitignored); specs start signed in as alice and call `openHome(page)`, open another member with `contextAs(browser, 'bob')`, and use `test.use({ storageState: ANONYMOUS })` only when the sign-in flow itself is under test (helpers in `e2e/helpers.ts`, fixtures in `e2e/fixtures/`). Never trigger a token refresh with the shared session (single-use refresh tokens); clean up data other specs rely on; scope locators (`exact: true`, `within` a region) because the sidebar renders Follow buttons too.
- Secrets only via environment variables; commit `.env.example` files, never `.env`. First run: `cp apps/api/.env.example apps/api/.env`.
- Database: schema lives in `apps/api/prisma/schema.prisma` (UUID v7 ids, snake_case via `@map`, `timestamptz`). Every schema change ships with a migration in the same PR (`pnpm db:migrate -- --name <change>`); never edit an applied migration. Prisma config is `apps/api/prisma.config.ts` (Prisma 7: no `url` in the schema, `.env` loaded there via dotenv).
- Integration tests (`pnpm test:int`) need Docker: they start a throwaway Postgres with Testcontainers unless `TEST_DATABASE_URL` is set (CI). They ignore `DATABASE_URL` on purpose and truncate the tables they use. The harness sets `DOCKER_AUTH_CONFIG` to an empty anonymous config because only public images are pulled; this also sidesteps Docker Desktop's Windows credential helper, which cannot be spawned from WSL (`appendWindowsPath = false`).
- pnpm 11 only runs approved postinstall scripts (`allowBuilds` in `pnpm-workspace.yaml`). When a new dependency brings a build script, pnpm inserts a placeholder line `'<pkg>': set this to true or false` into that file and fails fresh installs until it is replaced with `true` or `false` (deny telemetry/optional native builds, allow only what the app needs). A local `pnpm install` that is "already up to date" skips this check, so verify with a clean install: `git worktree add /tmp/wt HEAD && cd /tmp/wt && pnpm install --frozen-lockfile`. `pnpm approve-builds` also rewrites the file and can drop the catalog; re-check it afterwards.

- Deployment: images are built by `.github/workflows/docker.yml` and pulled by the server (`deploy/update.sh` on a systemd timer); there is no push deploy. Runtime configuration is environment only (`deploy/.env.example`); the API refuses development defaults in production (`PUBLIC_ASSETS_URL`, `WEB_ORIGINS`, `TRUST_PROXY`, placeholder `JWT_SECRET`, `COOKIE_SECURE=false`). `prisma` and `dotenv` are runtime dependencies of the API on purpose (migrations run from the container).
